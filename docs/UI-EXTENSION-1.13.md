# UI extension record: targeted media and the full Memes pad, 1.13 correction

This correction addresses two gaps in [1.12](UI-EXTENSION-1.12.md): generic media keys could control a different player, and browsing the Soundpad library did not make that whole library available on the tablet's Memes pad. It adds app-targeted Windows media sessions, compact context strips, and a runtime live Soundpad source for an existing board page. The incumbent world remains authoritative: Manrope, charcoal canvas, tonal surfaces, ivory/secondary text, cyan actions/focus, outline dividers, and rounded controls. No product/design authority or sidecar is regenerated.

The companion source and Android manifest now declare **1.13.0 / Android code 16**. The target framework is `net10.0-windows10.0.19041.0`, making Windows 10 version 2004 / build 19041 the minimum Windows version for this source. `WindowsSdkPackageVersion` is explicitly pinned to **10.0.19041.57**. Its Windows SDK reference pack is a source restore/build dependency; the published self-contained app does not require users to install the .NET or Windows SDK. The included `WINDOWS-SDK-LICENSE.rtf` and `CSWINRT-LICENSE.txt` retain the relevant SDK/CsWinRT notices. There is no `global.json` SDK pin. Packaging, publication, and deployment remain separate completion steps.

## Selected media players rather than global transport

In tablet **Computer Copilot**, the Spotify and YouTube layouts now mount `media-touchbar.js` instead of their legacy shortcut controls. The app-layout rail remains the way to choose the destination; the PC still owns enablement and saved layout configuration. The editor explains that playback, progress, and app volume use a selected Windows player, and hides the old playback/system-volume binding controls for those two layouts. Other app layouts remain editable shortcuts.

`MediaSessions.cs` enumerates Windows System Media Transport Controls sessions. Spotify matches only the supported exact desktop/Store source identities and invokes the selected session's native Play/Pause/Previous/Next/seek operations. It does not send global media keys, choose Windows' preferred/current player, fall back to a browser, launch Spotify, or use the Spotify Web API. A missing Spotify session is shown as missing. A single eligible Spotify session can be selected automatically; otherwise **Playback target** provides the choice.

The YouTube layout lists eligible browser players by their actual title and source and requires the user's explicit selection. Windows exposes the browser's media session, not its URL or website; the interface states **Website not identified**. A Chrome title is therefore not proof that the player is YouTube. Changing presets or playback targets cancels pending gestures rather than redirecting them.

The player displays actual title, artist/album fallback, optional embedded artwork, playing/paused source, elapsed/total time, and supported transport controls. Missing or unsupported capabilities are hidden/disabled with readable status. A neutral inline music symbol appears when artwork is absent; it is not sample album art. No remote artwork URL is fetched. The main media layout uses artwork beside metadata and continuous controls, with the title as its hierarchy anchor; narrow screens put transport/timeline across the full width. It inherits the existing palette and focus rules rather than adding a new media theme.

Media metadata refreshes about once a second while the view is active. Native snapshots cache for 500ms, share in-flight reads, bound session/metadata/artwork sizes, and use platform deadlines. The native reader estimates a playing track's position from its reported timestamp/rate only when those values and duration are usable, clamping to track bounds; this is display progress, not a seek or a guarantee about the player's internals.

Every write resolves the exact live session again and checks its track token and fresh capability/state. Replaced sessions, changed tracks, unsupported seek ranges, concurrent commands, and refused player operations return an error. Previous/Next invalidate the old track controls immediately. Seek retains the session/track identity from drag start and sends the final chosen position; a refresh cannot silently retarget that gesture to a new track. The host also checks that Computer Copilot is enabled, that the matching media layout is active, and that shared maintenance/action/held-key guards permit the operation. A track can still change inside the player after validation: the Windows API does not offer an atomic application-track transaction.

Volume uses the existing application mixer only for an exact known source-to-process mapping. One matching output can be selected automatically; multiple matches require **Audio output session** selection. The labels distinguish **Spotify volume** from **Browser volume (all tabs)**. Browser volume changes the application's output, including other tabs; it is not per-video volume. Missing matches never fall back to system volume or another application. Suspend, hidden/background state, and destination changes cancel pending media/volume gestures. See [MEDIA-CONTROLS.md](MEDIA-CONTROLS.md) for the native contract and bounds.

## Compact shortcut strips and relative Resolve jog

Nonmedia layouts now place related shortcuts in horizontal strips under restrained group labels. Common actions have inline SVG icons; labels and configured shortcuts remain visible. The layout rail and strips scroll horizontally where necessary instead of reproducing a second large board of generic keys. These are surface-specific arrangements within the existing type, color, border, and control vocabulary.

Resolve adds **Frame jog** only when its preset has configured non-global Left/Right shortcuts. Dragging away from center repeats those saved controls at a bounded rate, with direction/speed based on the relative slider value. Release, cancellation, blur, mode change, suspend, or an execution error stops repetition and recenters it. It remains guarded keyboard input to the matching foreground app. It does not read Resolve's native playhead, know the timeline duration, set an absolute timecode, or establish a deep Resolve API integration. The other editing/assistant strips retain their focus/keymap limitations and unassigned assistant commands.

## Put all Soundpad entries on Memes without bulk imports

The relevant PC path is **Stream Studio → Board editor → page dropdown → Memes**. Users can select an existing Memes page or create one in the current profile, then enable **Use the full live Soundpad library on this page**. **Soundpad playback output** offers **Discord / microphone**, **Speakers and microphone**, or **Speakers only**. Save applies the source/output to the tablet. The initial live output is mic; the destination app still needs Soundpad's correctly configured microphone route.

On the tablet, select Memes in the normal Studio page navigation. Its pad now comes from every entry in the running Soundpad source, rather than only the manually saved buttons. Full pad's 24/40 density limits the number visible in one group, not the library size. **Search all Soundpad sounds**, **Soundpad category**, Clear, group navigation, and **Jump to sound page** reach the full runtime set. Counts distinguish matches from the total. An unavailable source or empty filter shows the corresponding recovery guidance.

The observed development library contains **1,421 source entries**. The source permits up to **5,000**, while the isolated new live-board tests use **2,007 generated entries**; that fixture size is not an actual user-library claim. There is no need to duplicate thousands of manual buttons, bulk-import sounds, or split them into extra profiles. The separate 80-row Soundpad library browser remains available for explicit Play, favourites, and selected manual imports.

Only one page per profile can be live Soundpad, and a page cannot be both live OBS and live Soundpad. Enabling another page transfers the live flag while retaining each page's raw manual buttons; disabling live Soundpad and saving restores those manual buttons. Runtime entries are generated for the board, not persisted as thousands of configuration actions. Live pages suppress manual arrange/edit controls until their source mode is disabled.

The board polls about every five seconds when it has a live Soundpad page, outside arrangement work. Search includes full source names/artist/category data; page selection is clamped after changes. Focus follows stable sound identity where possible, with search fallback if a key disappears. Generated actions are accepted only for a currently live page. Their displayed index is not trusted for playback: execution resolves the current unique file identity immediately before the Soundpad command. Missing or duplicated identities cannot silently play a different indexed sound. Auto refresh never requests playback.
