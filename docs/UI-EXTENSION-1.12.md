# UI extension record: Computer Copilot and live libraries, 1.12

This ordinary extension adds a contextual computer-control mode, optional viewing of a separately created Windows desktop, continuously synced OBS scene pages, and complete Soundpad pagination. The [1.11 extension](UI-EXTENSION-1.11.md) remains the desktop lifecycle and updater baseline. The durable story stays **configure on the PC, operate on the tablet**. No `PRODUCT.md`, `DESIGN.md`, or design sidecar is created or replaced.

The incumbent `style.css` remains visual authority: bundled Manrope, charcoal canvas (`#101318`), layered dark surfaces, ivory ink (`#f5f7fa`), secondary text, outline dividers, cyan (`#78dce8`) actions and keyboard focus, rounded controls, and the existing confirmation/editor patterns. `computer.css` extends those rules rather than defining another palette. This record describes shipped source and saved evidence; it does not turn a surface-specific composition into a new global design rule.

## Mode selection and PC editing

The Windows header and tablet header each expose a labelled mode selector with **Stream Studio** and **Computer Copilot**. Studio retains its existing management console or live board. Computer mode uses a separate scrollable workspace and hides the tablet's studio grid, page navigation, and studio-only tools. The selected mode is saved locally. Mode changes stop display viewing and monitoring, ask before discarding dirty edits, and refuse while actions, held keys, or arrangement work make switching unsafe.

On the PC, Computer Copilot shows a management summary: enabled state, automatic/manual selection, foreground executable, current layout, and saved-layout count. **Edit Copilot settings** opens the existing inline editor. The PC edits the enabled toggle, **Follow supported foreground apps**, manual/fallback layout, layout name and executable associations, and each control's label, group, shortcut, and global flag. It can add/remove layouts and controls. Save sends the complete validated settings; controls remain disabled during a save, errors stay visible, and panel generation/ownership checks prevent late replies updating a replacement destination. The tablet runs the saved controls; it does not author PC shortcuts.

Computer Copilot starts **disabled**. Its automatic-selection preference starts true but does not enable execution. Supplied layouts are Desktop, YouTube, Spotify, Codex / GitHub Copilot, Claude, DaVinci Resolve, and Photoshop. These are editable keyboard-shortcut presets, not native deep integrations with those products. Assistant-panel controls begin unassigned, and no default Send action is supplied. Empty shortcuts cannot run; Enter-containing Computer shortcuts are rejected. The feature does not inspect chats or submit prompts.

Automatic selection reads the foreground executable name only. Exactly one matching layout can follow it; ambiguous or unmatched processes retain the manual/fallback layout. It does not inspect window titles, browser tabs, URLs, document text, or clipboard content. YouTube and browser-based Claude therefore require manual layout selection. Choosing a tablet layout saves it as manual and disables following until the PC setting enables it again; choosing a layout never launches or focuses an app.

On the tablet, a horizontal app-layout rail precedes the active layout, foreground/mode text, and grouped touch controls. Selected layouts use cyan against the higher surface; controls retain the familiar rounded dark button form, large labels, and smaller shortcut hints. Missing focus, disabled settings, missing bindings, or lost connection disable inappropriate controls and explain recovery. Non-global actions require a matching foreground executable; global actions are restricted to Windows media keys and app switching. Each request carries current context identity so stale window/layout/settings state is refused. Windows focus can still change at injection time, and elevated-app restrictions still apply.

The layout rail scrolls rather than compressing all choices into narrow labels. The selected layout is revealed when it changes or the viewport resizes, while ordinary refreshes preserve rail and workspace scroll positions. Groups flex across available space; smaller layouts use three control columns, then two below 420px. Desktop management uses the console's second grid track, and its editor takes the existing inline panel. These are source provisions with the isolated render coverage below, not physical tablet touch approval. See [COMPUTER-COPILOT.md](COMPUTER-COPILOT.md) for the controller contract; its standalone controller's false display capabilities are separate from the integrated `ExtendedDisplay` service.

## Optional independent Windows display

**Second display** is an expandable section within Computer mode. Contextual controls work without it. The integrated `ExtendedDisplay.cs` service discovers an already-installed compatible **SudoVDA 0.2 protocol** interface, checks local catalog/package trust and current topology, and reports availability separately from an active session, independent desktop, and enabled tablet sharing. No display driver is included, downloaded, installed, elevated, or repaired by opening this feature. Local trust is not a WHQL certification claim.

The PC shows the installed driver's information and offers 1280 × 800, 1600 × 900, or 1920 × 1080 at 60 Hz. **Create independent display** stays disabled until the user explicitly accepts both use of that installed driver and visibility of the extra display's pixels to the paired tablet. This UI sends both accept-driver and share-with-tablet intent. Creation/removal/sharing are local-admin operations; paired tablets cannot create monitors. If Windows has not exposed an independent extended source, the interface directs the user to Windows Display settings rather than silently changing physical monitor layout or mirroring a physical screen.

Only this session's newly created monitor is eligible for capture and cleanup. The backend refuses a competing active SudoVDA session, clone/overlap topology, absent or changed monitor identity, and unshared capture. It never chooses an existing physical desktop as fallback. A failed remove keeps ownership for retry and turns sharing off. **Pause tablet sharing** revokes access to new frames; enabling it again asks for explicit confirmation. **Remove extra display** explains Windows' window relocation before confirmation.

Once active, independent, and shared, the tablet offers **Open display view** and **Back to controls**. The preview sends bounded JPEG frames at up to four captures per second, with no audio; the tablet requests 960px width. The backend supports 640/960/1280px requests and a 384 KiB JPEG limit. Busy capture is dropped instead of queued. The tablet uses a single pending request, generation checks, and explicit pause/error feedback; mode changes, hidden/background or native pause, page exit, and revoked availability stop viewing and clear the image. Native resume does not automatically restart capture. This is a preview for tools/reference panels, not a full-motion remote-desktop claim. Touch/mouse forwarding into that desktop remains pending and is not supplied by this transport. See [EXTENDED-DISPLAY.md](EXTENDED-DISPLAY.md).

## Continuous OBS scene pages

**Import OBS scenes** now enables live sync on the Scenes page instead of copying a one-time button list. The board editor also offers **Keep this page synced with live OBS** for the selected page. It follows scene additions, renames, removals, and OBS order. Saved manual buttons remain in the configuration; live mode hides their editing/arrangement controls, and disabling the toggle restores them. Other manual scene/action pages continue to work.

The companion generates current scene controls when serving the board and includes a scene-catalog revision. State revision changes trigger refresh for live pages without another import. UUID-backed scene identities survive renames where OBS supplies them; execution resolves against the current scene list and refuses a removed scene. Older name-backed identities cannot promise rename continuity. The live page follows OBS order; users reorder in OBS or disable sync before arranging manually. With OBS unavailable, the page shows connection guidance instead of stale generated buttons. Mocked scene-catalog tests do not establish a real OBS session or broadcast.

## Complete Soundpad pagination and refresh

The Soundpad library retains search, category/output selection, favourites, playback, and PC import selection. **Previous**, **Next**, and **Sound page** now expose all matching sounds in pages of 80, with a visible range/total and boundary-disabled controls. A 1,421-sound library has 18 pages, ending with 61 sounds; the saved isolated test visits every one of those fixture entries. This removes the earlier initial-page accessibility limit and does not bundle a third-party library.

Search and category changes return to page one. The open, visible library refreshes every five seconds without overlapping reads. Unchanged data avoids needless rendering; changed data rebuilds categories, clamps the current page, and retains selected sounds through stable identity where possible. A changed quiet refresh also restores keyboard focus by stable sound identity and preserves panel scroll; if that sound disappears or moves off-page, focus falls back to the page selector. Favourites and missing/duplicate identity behavior remain from the existing system. Automatic refresh does not play sounds; only an explicit Play action requests playback.
